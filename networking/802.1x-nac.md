# 802.1X & Network Access Control (NAC)

## TL;DR
802.1X authenticates devices/users before granting network access at the port/SSID level — preventing rogue devices from plugging in. NAC extends this with posture checks and dynamic segmentation. Core of wired/wireless access control and Zero Trust networking.

## 802.1X components
```text
Supplicant     – the client (device requesting access).
Authenticator  – the switch/AP (gatekeeper of the port/SSID).
Authentication server – RADIUS (e.g. FreeRADIUS, Cisco ISE, ClearPass) validating credentials.
Protocol       – EAP over LAN (EAPOL); many EAP methods (see below).
```

## EAP methods (pick strong ones)
```text
EAP-TLS       – mutual certificate auth (strongest; no passwords). Preferred.
PEAP / EAP-TTLS – server cert + inner password (MSCHAPv2). Client MUST validate the server cert.
EAP-MD5       – weak, no server auth — avoid.
Risk: without server-cert validation, an evil-twin RADIUS captures MSCHAPv2 -> offline crack.
```

## NAC capabilities
```text
- Posture assessment (AV present, patch level, disk encryption) before/after access.
- Dynamic VLAN assignment / dACLs based on identity + posture.
- Guest/BYOD onboarding, profiling of device type.
- Quarantine non-compliant or unknown devices.
```

## Bypass techniques (attacker view)
```text
- MAC Authentication Bypass (MAB) abuse: spoof a whitelisted device's MAC (printer/IoT).
- Bridge/hub behind an authenticated device to piggyback the session.
- Rogue RADIUS / evil twin to capture EAP credentials (weak EAP + no cert validation).
Tools: nac_bypass, Silent Bridge; awareness for defensive testing.
```

## Detection (Blue Team)
- RADIUS logs: auth failures, MAB for devices that should do 802.1X, duplicate MACs.
- New MACs on authenticated ports; posture failures; evil-twin RADIUS indicators.

## Mitigation / Hardening
- Prefer **EAP-TLS** (certs, no MAB where avoidable); enforce server-cert validation on clients.
- Limit MAB scope; profile + monitor IoT; port security + dynamic segmentation.
- Combine with Zero Trust (don't trust a device just because it's on the LAN).
